# 第五阶段 Release 性能记录

测量开始于 2026-09-10 23:05（UTC+8）。短阶段与 20 次恢复已完成；30 分钟连续待机被中途隐藏打断。用户选择先查看代码和已完成实测，长时间验收留到后续，测量程序及其 WebView2 子进程已停止。

## 环境与测量口径

- Windows 11 家庭中文版，10.0.26200；WebView2 146.0.3856.97。
- Intel Core i5-13420H，8 核 / 12 个逻辑处理器，约 16 GiB 内存；Intel UHD Graphics 集成显卡，驱动 31.0.101.4502。
- 一个 1920×1200、60 Hz 显示器，Windows 缩放 125%；平衡电源方案。电池状态采样为 2，电量 100%。
- 窗口为 340×440 个逻辑像素；实际 Canvas 为 324×394，Pixi resolution=1，modelZoom=2.6。
- 两张 4096×4096 RGBA 贴图，PNG 共 11,092,835 字节。原始 8K 文件保持原样。
- 使用 `--no-bundle --features perf-audit` 的优化版可执行文件，前端设置 `VITE_PERF_AUDIT=1`。未打开 DevTools，未运行 Vite；本次没有制作安装包。
- 模型实际 `update` / `draw` 方法被探针计数，每 5 秒上报。Rust 通过同一个窗口服务切换状态。PowerShell 读取主程序和 7 个 WebView2 子进程，采样间隔为 5 秒加上读取耗时。
- 每个稳定阶段排除开头 10 秒的切换边界，使用约 110 秒的有效帧计数。CPU 为整组进程 CPU 时间增量除以经过时间、再除以 12，表示整机百分比；内存列使用样本中位数。
- 采样与窗口切换工具有额外开销。其他桌面程序正常运行，未锁频、未改变电源方案，也未测整机功耗，因此不把 CPU 降幅直接换算成续航提升。

## 已完成的短阶段

| 状态 | 原始阶段时长 | 更新/绘制次数每秒 | 平均 CPU | Private Bytes | Working Set 合计 | GPU 共享内存 |
|---|---:|---:|---:|---:|---:|---:|
| 可见，30 FPS | 120 秒 | 29.49 / 29.49 | 4.64% | 497.3 MiB | 850.9 MiB | 229.8 MiB |
| 可见，15 FPS | 120 秒 | 14.90 / 14.90 | 3.17% | 500.1 MiB | 859.2 MiB | 229.3 MiB |
| 隐藏 | 120 秒 | 0 / 0 | 采样精度下约 0% | 430.9 MiB | 792.0 MiB | 230.8 MiB |
| 最小化 | 120 秒 | 0 / 0 | 采样精度下约 0% | 501.7 MiB | 863.0 MiB | 231.3 MiB |

30 → 15 FPS 在这次短阶段中的平均 CPU 下降约 **32%**。这说明控制更新频率有实际收益，但可见状态仍有数个百分点的整机 CPU 消耗。

本机使用集成显卡，GPU 专用内存计数为 0；GPU 共享内存依然约 230 MiB。隐藏保留纹理，显存没有随绘制停止而释放，符合当前设计。

三个内存列是不同口径，不能相加。Working Set 求和可能重复计算共享页面；Private Bytes 是私有提交内存，不等于实际驻留 RAM；GPU 共享内存还涉及驱动和操作系统记账。

## 暂停与恢复

- 隐藏和最小化两个稳定阶段的更新、绘制增量均为 **0**。
- 此环境下隐藏或最小化后，页面仍上报 `pageVisible: true`。因此必须结合 Rust 显示设置及原生最小化状态，不能单靠 `visibilitychange`。
- 完成 20 次隐藏/显示，另有前面的隐藏恢复和最小化恢复，共 22 次暂停/恢复。
- 计划内 22 次暂停后检查，暂停期间最大更新增量、绘制增量均为 **0**；恢复首帧的最大模型步长为 **0 秒**。后续长时间阶段发生的额外操作单独视为中断。
- 全程模型实例 ID 一致。反复恢复后读取桌面截图，模型正常显示；采样期间无前端全局 error 或 unhandledrejection 事件。

这里验证的是应用窗口服务和真实模型行为。原生托盘菜单点击、手动拖动、系统关闭按钮转隐藏及跨不同缩放显示器的拖动，仍属于第四阶段保留的人工验收项；本机只有一个显示器。

## 连续待机 30 分钟

**未通过验收，也没有足够数据判断长期稳定性。** 连续待机开始约 390 秒后，原生窗口与 Rust 设置均转为隐藏；设置 revision 从 46 变为 49，后续模型停止更新。整个标记为待机的阶段记录了约 875 秒，但其中包含了隐藏时间，不能算作连续可见待机。

隐藏后的内存下降不能用于证明可见状态下不存在增长。汇总脚本已将该阶段标为 `continuousVisibleIdlePassed: false`，并省略容易误导的混合状态平均值。[deferred.json](deferred.json) 记录用户暂缓决定；本次没有 `complete.json`。

采样后补强了验收工具：连续待机中检测原生显示、最小化、30 FPS 设置、实际渲染状态、采样新鲜度及暂停计数；任一被打断则记录错误并退出。新增两项 Rust 测试覆盖错误状态不能通过的情况。该工具修正不改变桌宠正常功能。

## 复现与原始记录

在 `app/` 中按 [第五步学习说明](../../learning/05-performance.md) 的命令运行。为每次采样选择新目录；测量脚本会自动完成全部阶段并退出桌宠。

- [machine.json](machine.json)、[environment.json](environment.json)：硬件、系统与运行环境。

- [process-roles.json](process-roles.json)：区分 Rust、WebView2 browser、renderer 和 GPU 进程。
- [summary.json](summary.json)：通过汇总脚本从原始记录计算。

本次运行的早期采样脚本对 PowerShell 有序字典的内存合计字段写出了 `null`；逐进程的字节数完整。汇总脚本始终从逐进程原值重新求和，不把 `null` 当成 0，也没有修改原始采样文件。当前采样脚本已改用 `PSCustomObject` 修复该问题。

正常生产前端构建已检查不含 `pet-render-metrics`、探针模块和暂停计数标记。日常构建不会编译 Rust 的可选验收模块，也不会启动探针的上报定时器。
