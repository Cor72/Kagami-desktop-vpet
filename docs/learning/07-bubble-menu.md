# 点击表情、气泡菜单与独立设置

## 使用方式

| 操作 | 结果 |
| --- | --- |
| 左键单击角色 | 随机选择四个现有表情，排除最近收到的表情 |
| 按住左键移动至少 6 个逻辑像素 | 原生窗口拖动，松开不触发表情 |
| 右键角色 | 展开一级菜单，再次右键收起 |
| 表情 | 五个原位置替换为微笑、眯眼、泪眼、泪滴、返回 |
| 设置 | 打开唯一的“八千代 · 设置”窗口 |
| 置顶 | 切换实际置顶状态，淡紫和圆点表示开启 |
| 隐藏 | 收起菜单并隐藏角色，使用托盘恢复 |
| 退出 | 退出应用及设置窗口 |

Esc 从表情菜单返回一级，再次按下收起。Tab、方向键和 Enter/Space 可操作菜单。退场层设为 inert，避免动画切换期间键盘触发旧入口。开发联调和模型重载放在设置窗口；模型加载失败仍可在原位重试。

## 调用链

`PetStage` 通过 `createPetGesture` 区分单击和拖动。单击调用 `pickExpression`，随后沿用 `request_expression → pet-expression-requested → controller.setExpression`，不再使用 mousedown 立即拖动。

`App → menuController → set_pet_menu_open` 串行调整原生窗口。紧凑窗口为 340 × 440，展开为 480 × 440。角色画布保持原来的尺寸，菜单只占新增区域。原生布局返回 `side/modelOffsetX/menuOffsetX/menuTop/menuHeight/width/height`，单位均为逻辑像素。

右侧空间足够时保持窗口原点；右侧不足时窗口向左扩展，并将角色画布向右偏移等量距离。关闭使用当前窗口位置恢复锚点。工作区交集决定菜单可见高度，空间不足使用紧凑行，极窄可见区提供滚动。DPI 换算、负坐标屏幕和失败状态回滚在 Rust 中处理。

原生隐藏、恢复和失焦会发出 `pet-menu-layout-changed`。前端收到重置时再次明确同步关闭，避免跨事件通道的迟到响应遗留透明扩展窗口。快速开关和同一轮事件中的层级切换均只落实最终状态。

`main.js` 按 `?view=settings` 动态加载设置页；只有主窗口加载 Cubism Core、PetStage 和 Pixi。`usePetSettings` 在两个窗口监听 Rust 设置事件，再读取初始快照，利用 revision 防止旧数据覆盖新数据。设置窗口没有模型资源读取权限。

设置页的开发联调订阅独立的 `pet-expression-observed`；模型事件仍只发给主窗口。`reload_pet_model` 在开发版本发事件，发布版本拒绝执行。图标使用 ISC 许可的 `@lucide/vue`。

## 验证记录（2026-09-11）

- `pnpm test`：31/31，通过手势阈值、随机池、菜单层级、异步开关/重置、设置版本及现有渲染/跟随回归。
- `pnpm build`：通过；设置页独立分包，入口不加载 Core/Pixi。
- `cargo test --offline`：18/18；包括顶部/底部裁切、窄屏、负坐标、150%/200% DPI、锚点和失败回滚。
- `cargo fmt --check`、`cargo check --release --offline`：通过。
- Windows 实机：五球展开、表情二级原位替换、选择表情收起、独立设置窗口、设置中切换置顶、关闭设置后角色继续运行、退出按钮已验证。
- 独立代码审查发现并修复了迟到响应、旧层键盘激活和上下边缘裁切问题；复查无阻塞问题。

拖动测试已观察到原生窗口位置变化；自动化快速注入在拖动时序上不稳定，完整的按住、快速松开及移出窗口还需实际鼠标验收。跨不同 DPI 的物理双屏拖动、长时间反复开关、全部托盘交互也需要实际设备验收，不能以纯几何单元测试替代。

用户报告的 `Monitor.work_area` 私有字段编译错误已改为公开方法 `work_area()`；本机的 Cargo config 弃用提示不影响编译。
