# 八千代桌宠：点击表情与气泡菜单改造计划

> 按用户确认的方案实施。下方复选框区分已完成的实现与仍需实际设备覆盖的人工验收，详细记录见 docs/learning/07-bubble-menu.md。

**状态：** 2026-09-11 已实现。五个一级入口、二级原位替换、设置独立窗口、鼠标跟随均已接入；前端 31 项、Rust 18 项测试和构建通过。实机已验证主要菜单及设置流程，跨 DPI 多屏等扩展验收另列。

**目标：** 左键单击角色随机切换表情，右键在角色右侧展开五个圆球；表情二级菜单原位替换一级菜单，设置直接打开独立窗口。

**架构：** Tauri 主窗口继续承载唯一的 Live2D 模型，在 Vue 中增加手势识别和气泡菜单；通过临时扩展主窗口容纳一组菜单，固定角色画布尺寸和屏幕位置。设置窗口按需创建，不加载模型，与主窗口和托盘共享 Rust 设置状态。沿用当前鼠标跟随、表情和 15/30 FPS 功能。

**技术栈：** Vue 3 + JavaScript + CSS、Tauri 2 + Rust、PixiJS 8 + easy-live2d 0.4.4。气泡是可访问的 HTML button，使用现有技术栈；不新增 UI 框架或动画库。

**设计依据：** 本文“交互约定”和“视觉约定”，以及 [气泡菜单修订效果图](../../design/2026-09-11-bubble-menu-v2.png)。图用于确认风格和层级，图中角色为生成示意，实现时继续使用项目现有 Live2D 模型，不改服装或模型资源。首版图只作历史参考，不再作为实现目标。

**出图方式：** 内置 Image Gen，以首版效果图为编辑目标，保留角色、材质与配色。[修订提示词](../../design/2026-09-11-bubble-menu-v2.prompt.txt)。

## 一、交互约定

### 左键：单击与拖动分开

| 输入 | 结果 |
|---|---|
| 在角色交互区域按下并松开，位移不足 6 个逻辑像素 | 随机切换一个现有表情 |
| 按住左键移动达到 6 个逻辑像素 | 开始原生窗口拖动，松开不切换表情 |
| 右键角色 | 菜单关闭时打开一级菜单；菜单打开时收起全部层级 |
| 左键点击菜单圆球 | 仅执行圆球操作，不触发随机表情或拖动 |
| 菜单打开时左键点击角色 | 收起菜单，并按单击规则切换随机表情 |

- 使用当前已有的 `smile / squint / tears / teardrop` 四个表情，不引入新模型资源。
- 随机池排除最近一次实际收到的表情；连续单击不会视觉上重复同一表情。
- 表情保留到下一次切换，不自动启动轮播或恢复计时器。
- 复用 `usePet.sendExpression()` 和 `sending` 状态，通信未就绪或请求进行中不重复发送。
- `pointercancel`、失焦、卸载都会清除手势状态；拖动触发后抑制后续合成 click。
- 必须移除当前 `mousedown` 立即调用 `startDragging()` 的行为，否则无法稳定区分单击和拖动。

### 一级菜单：五个圆球

| 圆球 | 图标 | 操作 | 成功后的菜单状态 |
|---|---|---|---|
| 表情 | 微笑线条图标 | 进入表情二级菜单 | 隐藏全部一级入口，在相同五个位置显示二级内容 |
| 设置 | 齿轮线条图标 | 打开独立设置窗口 | 收起气泡菜单，设置窗口获得焦点 |
| 置顶 | 图钉线条图标 | 切换保持置顶 | 保留一级菜单，以实际设置显示选中状态 |
| 隐藏 | 隐藏视线图标 | 调用现有隐藏命令 | 关闭，窗口隐藏 |
| 退出 | 电源线条图标 | 调用现有退出命令 | 退出应用，连同设置窗口一起关闭 |

仅“表情”带进入下一级的小箭头；“设置”直接开窗，不带子菜单箭头，其余操作也不带箭头。操作错误时不伪装成功，保留可重试入口并显示简短错误提示。

### 表情二级菜单：同一组位置换内容

**五个位置依次显示：** 微笑、眯眼、泪眼、泪滴、返回。它们与一级的五个圆球共用完全相同的位置、尺寸和排列；进入二级时一级全部隐藏，不保留分类圆球、不在更右侧新增一列。

点击四个表情项，通过现有 Rust 事件驱动模型切换，命令成功后收起菜单。第五个“返回”只恢复一级五个入口，不改变模型表情。

- 菜单始终只显示一层内容，可用状态只有 `closed / root / expressions`。没有设置二级菜单。
- 层级切换只替换菜单内容，不扩大窗口、不移动菜单、不缩放角色；退出层隐藏后再让进入层可交互，不叠加两组可点击圆球。
- 点击“返回”回到一级；Esc 先从二级返回一级，再按 Esc 关闭全部。
- 点击本窗口菜单外空白、再次右键、窗口失焦、开始拖动或主动隐藏时关闭菜单。
- 移动鼠标经过圆球之间的间隙不关闭菜单，避免难以点击二级项。
- 键盘可用 Tab 切换、Enter/Space 激活；收起后将焦点交还角色交互入口。

### 设置：独立窗口

- 点击一级“设置”，直接打开标题为“八千代 · 设置”的常规窗口，建议初始尺寸 360 × 300，可按内容高度调整。
- 首版提供“帧率：30 FPS / 15 FPS”和“保持置顶”。置顶既能通过一级圆球快捷切换，也能在设置中调整，两处显示同一份真实状态。
- 关闭按钮只关闭设置窗口，不退出或隐藏角色；隐藏桌宠也不自动关闭设置窗口。关闭后销毁设置 WebView，再次打开时重新创建。
- 设置窗口使用固定 label `settings`；重复请求只显示并聚焦已有窗口，不重复创建。不强制置顶、不使用透明背景。
- 设置页只加载 Vue 设置界面，不实例化 PetStage、Pixi 或 Cubism。开发模式额外显示“联调”入口，在设置窗口内打开现有 DevPanel；其中的表情按钮仍控制主窗口模型。
- `pet-settings-changed` 同步到主窗口和设置窗口；`pet-expression-requested` 仍只发送到主窗口，避免设置窗口重复处理模型事件。设置页需要表情反馈时单独订阅结果，不创建模型。
- 当前 `usePet` 混合了模型可见性、最小化监听和设置状态，不能直接完整挂载到设置页；应提取共享设置订阅或为设置页增加精简 composable。
- 托盘恢复角色、隐藏和退出行为保留。打开设置导致主窗口失焦时只收起菜单，不暂停鼠标跟随与模型渲染。

## 二、视觉约定

- 默认只保留角色，去掉底部“联调 / 隐藏 / 退出”和运行状态工具条；功能分别收进气泡菜单、开发联调面板和原生托盘。
- 一级五个圆球在角色右侧纵向轻微弧形排列，覆盖肩部到裙摆附近的可用空间，避开脸部；五个标签均完整显示。
- 一级和二级球统一直径约 52 px，共用五个位置。二级第五球为“返回”，不再另放一个返回按钮。
- 暂定菜单槽内五个中心的纵坐标为 48、130、212、294、376（逻辑 px），圆球下面放短标签；最终按真实模型与 440 px 窗高核对。五个中心横坐标略有弧度，层级切换前后不变。
- 使用暖白半透明底色、细白边、柔和阴影、深紫线条图标；淡紫表示选择态，薄荷绿和浅粉只作少量点缀。
- 色彩沿用项目：主色 `#73558c`，辅助紫 `#b19bc3`，暖白 `#faf7f2`，深色文字 `#3d3545`。
- 圆球下方显示短标签，不要求用户猜图标。图标使用许可明确的现成线条图标资源。
- 展开动画约 180–220 ms，按顺序轻微缩放、位移和淡入；悬停放大约 1.06 倍，按下缩小到约 0.94 倍。层级切换在原位先退场、再进场，始终只有当前层可点击。
- 菜单显示稳定后不做持续漂浮、闪烁或粒子动画。尊重 `prefers-reduced-motion`。
- 效果图在一张画布中展示同一方案的“一级菜单”和“表情二级菜单”，不是两个不同方案。

## 三、窗口与屏幕边缘

当前主窗口为 340 × 440，CSS 超出窗口不能显示，因此菜单需要原生窗口布局配合。

1. **关闭状态：** 维持 340 × 440。角色渲染槽保持改造前的实际舞台尺寸，通过布局定位，不能因去掉工具栏而意外放大模型。
2. **展开状态：** 暂定宽度 480、高度 440。新增的 140 px 足够容纳一组五球弧形菜单，不再为并排二级保留额外列；一级/二级使用相同窗口尺寸，切换层级不会反复伸缩。
3. **角色锚点：** 主窗口扩大时只增加菜单区域，原角色画布不随 flex 增长，不重新按窗口宽度 fitModel。展开、切换层级、收起均保持角色屏幕位置不变。
4. **右侧空间不足：** 根据当前显示器 `work_area` 判断；优先右侧，放不下则在左侧镜像展开。左侧展开时窗口原点左移、角色局部位置相应右移，保持角色原地不跳动。
5. **边缘与缩放：** 坐标统一使用逻辑像素，原生边界计算明确进行物理/逻辑换算。靠上、靠下时调整菜单内部纵向位置；工作区过小则使用紧凑排列，仍保持可点击。
6. **异步操作：** 原生布局请求串行执行；快速开关只接受最新目标状态，卸载和隐藏最终恢复紧凑布局。失败时保留原布局并恢复菜单状态。
7. **鼠标跟随：** 继续使用真实 canvas DOMRect 计算视线，不能把菜单扩展区算进角色画布；左侧展开产生的画布局部偏移也应正确扣除。

透明的原生窗口区域仍可能拦截桌面点击，单靠 CSS `pointer-events: none` 不能解决。首版只在菜单打开时临时扩容，收起立即还原，不增加常驻透明大窗口；逐像素穿透不包含在本次改造内。

### 任务 2：随机表情与菜单状态

**接口：** `pickExpression(expressions, previous, random = Math.random)` 返回表情名或空池时的 `null`；`transitionMenu(state, action)` 管理 `closed / root / expressions`；`getMenuItems(state)` 返回当前层的条目。打开设置是独立命令，不进入菜单状态机的下一级。

代表性预期，使用固定随机源避免测试偶发失败：

```javascript
assert.equal(pickExpression(['smile', 'squint', 'tears', 'teardrop'], 'smile', () => 0), 'squint')
assert.equal(pickExpression(['smile'], 'smile', () => 0), 'smile')
assert.equal(pickExpression([], '', () => 0), null)
assert.equal(transitionMenu('closed', 'context'), 'root')
assert.equal(transitionMenu('root', 'expressions'), 'expressions')
assert.equal(transitionMenu('expressions', 'back'), 'root')
assert.equal(transitionMenu('root', 'escape'), 'closed')
assert.deepEqual(getMenuItems('root').map(item => item.id), ['expressions', 'settings', 'always-on-top', 'hide', 'quit'])
assert.deepEqual(getMenuItems('expressions').map(item => item.id), ['smile', 'squint', 'tears', 'teardrop', 'back'])
```
